# Database Design

PostgreSQL is the central source of truth. This document defines conventions, ownership classes and policy. The table-by-table catalog is [`ENTITY_CATALOG.md`](ENTITY_CATALOG.md); isolation is [`ISOLATION_AND_RLS.md`](ISOLATION_AND_RLS.md). **No migrations exist yet** (Phase 1 creates them); everything here is design.

## 1. Conventions

| Topic | Rule |
|---|---|
| Identifiers | UUIDv7 primary keys generated by the application (time-ordered → index-friendly). Human-facing codes (voucher numbers, company codes) are separate columns. |
| Names | `snake_case`, plural table names, `*_id` foreign keys, `*_at` timestamps (`timestamptz`, UTC) |
| Money | `NUMERIC(20,6)` + `currency_code CHAR(3)` (ISO 4217). Never `float`/`real`/`double precision`/`money`. Rounding to `currencies.minor_unit` at defined points only (ADR-008) |
| Quantities / rates | quantities `NUMERIC(20,6)`; tax/percentage rates `NUMERIC(12,8)`; FX rates `NUMERIC(20,10)` |
| Tenant columns | Tenant-owned: `organization_id NOT NULL`. Company-owned: `organization_id NOT NULL, company_id NOT NULL` + composite FK (ADR-002) |
| Audit columns | `created_at`, `created_by`, `updated_at`, `updated_by`, `row_version INT` (optimistic concurrency) on mutable tables |
| Deletion | Configuration: `archived_at` (soft). Immutable/financial: never deleted by the app role. Real deletion only by retention/erasure job (see §5) |
| Enums | Text columns with `CHECK` constraints (or lookup tables) rather than native PG enums, so values can evolve by migration without type rewrites |
| Flexible data | `jsonb` only for validated, versioned documents (snapshots, template definitions, mapping specs, provider raw results) — never for data the application filters/aggregates on (custom field values are typed rows, ADR-007) |
| Text | Case-insensitive uniqueness through `citext` or lower() unique indexes where names must be unique among siblings |
| Time-series tables | `audit_events`, `usage_records`, `company_change_log`, `document_processing_jobs` partitioned by time (monthly) |
| Search | `pg_trgm` GIN indexes for fuzzy duplicate and name search; full-text search added when needed |

## 2. Ownership classes (every table must be classified; CI enforces)

| Class | Meaning | Columns | RLS pattern |
|---|---|---|---|
| **P — Platform** | Owned by Artify; not tenant data | none | platform-role only |
| **R — Reference** | Artify-managed read-only reference data (document kinds, currencies, permissions, entitlement definitions) | none | readable by all, writable by owner only |
| **T — Tenant** | Belongs to an Organization | `organization_id` | tenant isolation |
| **C — Company** | Belongs to a Company inside an Organization | `organization_id`, `company_id` | company isolation (+ section rule where relevant) |
| **U — User** | Belongs to an individual identity | `user_id` | own-row policy |
| **D — Document/transaction-bound** | Child of a specific document/transaction; inherits Company scope and carries `company_id` too | `organization_id`, `company_id`, parent id | company isolation + FK to parent |

organizations 1─* companies 1─1 workspace_configurations
organizations 1─* organization_memberships *─1 users
companies     1─* company_memberships    *─1 users

## 5. Retention, deletion and erasure

| Data | Policy |
|---|---|
| Original documents & financial records | Retained per configurable retention policy (decision D-8). Not deletable by users or the app role; archive only |
| Workspace configuration | Soft-archived. Hard delete only for nodes with zero references (see workspace doc) |
| Audit events | Append-only; retention ≥ longest financial retention; archived to cold storage by partition |
| Sessions/refresh tokens | Expire and purge after defined TTL |
| Usage records | Aggregated into counters; raw rows rolled up and archived by partition |
| Account/Company deletion | Request → grace period → export offered → controlled purge by `artify_retention`, with tombstones in the change feed and an audit entry. Legal hold blocks purge |
| Personal data (users) | Erasure requests handled by anonymizing user rows while preserving audit integrity (user id retained, PII removed) where law permits retention of the financial trail |

## 6. Migration policy

- All schema changes via Alembic migrations, reviewed; destructive changes use expand → backfill → contract across releases.
- Every migration runs in CI against an empty database and against the previous release's schema + synthetic data.
- RLS, triggers, and constraints live in migrations (not manually applied); CI checks `pg_policies` coverage (see isolation doc §6).
- A schema lint test asserts: no float types on financial columns, all tenant tables classified, every company table has composite FK, every immutable table has the immutability trigger.
- Seeds: reference data (document kinds, permissions, entitlement definitions, currencies) via idempotent seed migrations; jurisdiction packs and workspace templates are versioned data packages, not code constants.

## 7. Indexing guidance

Lead with `(organization_id, company_id, …)`; add `(company_id, status, created_at)` for work queues, `(company_id, sha256)` unique for duplicate detection, `(company_id, field_id, value_*)` for custom field filtering, GIN trigram on vendor/invoice-number keys, partial indexes on active (non-archived) rows for unique sibling names. Partition `audit_events` and `company_change_log` before they become large, not after.
