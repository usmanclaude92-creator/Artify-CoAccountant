# Phase 11 Completion Report — Mobile application (Flutter, Android and iOS)

Status: **delivered for review.** Phase 12 has not been started. **No Android or iOS binary was built, installed or run in this environment**: the Android SDK is not installed and cannot be downloaded through the sandbox's network policy, and iOS cannot be built on Linux. Everything marked tested was tested with Flutter's own test runner (no device, no emulator), the real controllers and repositories, a fake HTTP backend and synthetic photos.

Legend: **[Full]** fully implemented · **[Partial]** partially · **[None]** not implemented · **[Pass]** tested and passed · **[Fail]** tested and failed · **[Untested]** not tested.

## 1. Summary of the mobile application architecture
`apps/mobile` — Flutter 3.47 / Dart 3.13, feature-based (`core/`, `features/{auth,orgs,workspace,scanner,upload,documents,notifications,dashboard,settings}`), small `ChangeNotifier` controllers behind one `AppServices`, platform capabilities behind interfaces. It is a thin client of the existing FastAPI backend: same accounts, memberships, workspace configuration, upload protocol and device registry; no second auth, database, workspace or document engine. The server address is the only configuration (`--dart-define=ARTIFY_API_URL=…`); no secret is compiled in. ADR-079..081, [docs/mobile/ARCHITECTURE.md](../mobile/ARCHITECTURE.md).

## 2. Flutter project structure
See [ARCHITECTURE.md](../mobile/ARCHITECTURE.md). 47 Dart files in `lib/` (≈ 5 000 lines), 8 test files + support code, Android and iOS projects generated by `flutter create` and configured (identifiers, permissions, signing from external files).

## 3. Screens and workflows implemented
**[Full] (code complete, widget-tested where marked in §16):** welcome; sign in with password visibility toggle; second factor; forgot/reset password; session expired; app lock; organization list; company list with search and switching; home (greeting, active company, four quick actions, queue counts, resumable drafts, recent activity); folder browser (nested, ordered, descriptions); live scanner (camera, flash, camera switch, gallery fallback); page editor (draggable corners, "whole picture", colour/grey/B&W, brightness, contrast, shadow reduction, result preview); scan review (reorder, rotate, retake, adjust, delete, add page, apply mode to all, quality, save draft, discard); PDF preview; send form (folder, category, all ten metadata types, draft or send); upload queue; documents (paged, search, mine/all); document detail (status, location, category, version, picture preview, rename); notices and preferences; settings (profile, switching, biometric, storage and cache, privacy, help, about, sign out).
**[Partial]:** document detail previews pictures only (PDFs and other types are downloaded to the cache but not rendered; there is no share/save-copy action because no sharing plugin was added); no version-history screen (the number of versions is shown); "awaiting review" counts on the dashboard are not shown (no permission-safe count endpoint); company logo / last activity are not shown (the backend has neither).
**[None]:** push notifications; Arabic/RTL localisation; tablet-specific layouts; background upload while the app is closed.

## 4. Authentication integration — [Full], tested
Existing endpoints only: login, second factor (`mfa_required` / `mfa_enrollment_required` handled — enrolment itself is sent to the web/Windows app), refresh (single-flight, one retry), logout (server call, local wipe even if the call fails), password reset request/confirm, `GET /me`. Tokens in Keystore/Keychain via `flutter_secure_storage`; passwords never stored. Session expiry ends the session and shows its own page. Biometric lock protects an existing session only.

## 5. Organization and company selection — [Full], tested
Memberships from `/me`; companies from `/orgs/{id}/companies` (paged, archived hidden); several organizations and companies, switching without signing out, selection remembered, device registered per organization with the plan's limit shown as an instruction to ask the administrator. The active company is shown on Home and Settings; every company call is server-authorised (403/404 → "no access").

## 6. Dynamic workspace integration — [Full], tested
`upload-config` is the only source: sections and nested folders by stable id in the company's own order, categories (global or scoped to a folder and its descendants), fields scoped by category/folder, descriptions. ETag revalidation (304 costs nothing), "folders were updated" notice, last good copy per company for offline use, a mismatched company in the answer is rejected, nothing is hard-coded (tests with 4-section, 10-section, nested and empty companies). **One backend extension** (§11/§12).

## 7. Scanner capabilities
**[Full], tested on synthetic photos:** automatic page detection with honest "not found", perspective correction, rotation, brightness, contrast, shadow reduction, colour/grey/black-and-white, page model with originals preserved.
**[Full], not testable here:** live camera preview, flash modes, camera switching, permission-denied handling (code present; runs only on a device).
**[Partial]:** detection runs on the captured still, **not** continuously on the live preview (no live outline); quality depends on lighting and background; HEIC photos from the gallery rely on the OS picker's conversion; performance on low-end phones not measured. [SCANNER_AND_PDF.md](../mobile/SCANNER_AND_PDF.md).

## 8. Multi-page PDF — [Full], tested
Continuous capture into one session; page count, thumbnails, reorder, delete, rotate, retake in place, add pages, per-page and global look, draft save/resume, one PDF with pages in order (A4 width, shaped to each picture, JPEG 85 / 92), preview with file size, discard. The PDF preview shows the embedded pages; it is not a PDF renderer. Page order, page count and shape verified by tests.

## 9. Document upload workflow — [Full], tested
Camera scan, system file picker (Android/iOS), gallery; destination → category → company fields → name → send/draft; client checks for type, emptiness and the category's allowed types; the server's refusal (type, destination, validation, plan limit, duplicate) is shown in its own words; states Draft, Waiting, Uploading, Verifying, Verified in cloud storage, Failed, Cancelled, Quarantined; "completed" only on the server's confirmation; retry, cancel, upload-as-copy.

## 10. Offline upload queue — [Full], tested; byte-resume [None]
File-backed journal plus private copies; survives restart (mid-upload items return to waiting with the same idempotency key); runs on reconnect, on return to the foreground and by back-off; duplicate prevention (client and server idempotency); session expiry pauses without failing documents; originals kept until confirmation; cleanup on verification, cancel and sign-out. Not built: resume from a byte offset (backend takes whole files), uploading while the app is closed. [UPLOAD_QUEUE.md](../mobile/UPLOAD_QUEUE.md).

## 11. Backend APIs reused and created
**Reused:** `/auth/login`, `/auth/mfa/verify`, `/auth/refresh`, `/auth/logout`, `/auth/password-reset/*`, `/me`, `/devices`, `/orgs/{id}/companies`, `/companies/{id}/workspace/upload-config`, `/companies/{id}/documents` (list/get/content/versions/PATCH), `/documents/uploads` (register/content/complete), `/documents/{id}/intelligence`, `/documents/events`, `/documents/counts`.
**Created:** none (no new endpoint). **Extended (additive):** `upload-config` now includes `description` on targets/categories/fields, and `default_value`, `validation`, `reference_target` on fields. Test: `tests/test_p11_mobile_contract.py`.

## 13. Security implementation
Secure storage for tokens; no embedded secrets; server-side authorisation for everything; company/organization isolation tests at the cache and request level; generic notification text; no request/body/content logging; private storage for queued documents with deletion on verification/cancel/sign-out; HTTPS only in release (Android flag; iOS default ATS); release signing from external files. **Not implemented:** certificate pinning, root/jailbreak detection, screenshot blocking, encryption of queued files beyond the OS sandbox. [SECURITY_AND_PRIVACY.md](../mobile/SECURITY_AND_PRIVACY.md).

## 17. Known issues
* The live preview has no edge overlay; detection happens after capture.
* Image processing of very large photos is done in an isolate but has not been timed on real hardware.
* The documents list shows the folder path only when a workspace copy is cached; the detail screen cannot render PDFs.
* `flutter_secure_storage` and `local_auth` major versions are new; their platform behaviour is unverified.
* The notices list does not refresh in the background.

## 18. Incomplete features
Push notifications and their server endpoints; certificate pinning; root/jailbreak signals; screenshot policy; Arabic/RTL; tablet layouts; PDF/other-type rendering and sharing; version-history and metadata-edit screens; background and byte-resumable uploads; conditional field visibility (the backend has no rules for it); entitlement display beyond the server's refusal messages; company logo and last-activity; official icons and launch screens (a generated placeholder icon is in place).

## 19. Required manual configuration
Install Flutter and the Android SDK (and Xcode for iOS); build with `--dart-define=ARTIFY_API_URL=https://<server>/api/v1`; create an upload keystore and `android/key.properties`; Apple Developer account, App ID, certificate and provisioning profile; privacy policy URL and store listings; replace placeholder icons; choose a push provider if push is wanted; confirm iOS export-compliance answers.

## 20. Dependencies for Phase 12
1. **Synchronisation engine and contracts** — the app is only an upload queue; the sync states, conflict model and server revisions are Phase 12 work, and the app must not claim "synchronised" until then (it does not).
2. **Notification delivery** — push-token endpoint, delivery handler on the outbox events, provider choice.
3. **Resumable uploads** (byte ranges) if large-file reliability on mobile networks matters.
4. **Device verification** — someone must build and test on real Android and iOS devices before any release claim.
5. **Security testing** — certificate pinning decision, root/jailbreak signals, screenshot policy, penetration test of the mobile flows.
6. Entitlement and device-limit **display** data from the backend.

## Existing design and functionality preserved
The Windows app and web console were not changed in this phase. Backend change: one additive extension to a read endpoint. The brand tokens (teal accent, neutral surfaces, 8 px corners, light/dark) match the existing design system.

**Ready to start the Phase 12 work that is server-side or documentation-based** (sync architecture, conflict handling, security testing plan, backup/DR, release guides).
